# Правила версий

[English](versioning.md) · Русский

4VRS Gateway использует `vГОД.РЕЛИЗ.ИСПРАВЛЕНИЕ`. Это календарная схема
проекта, а не Semantic Versioning.

- ГОД — четыре цифры года первой публикации функционального выпуска.
- РЕЛИЗ — номер функционального выпуска в этом году, начиная с `00`.
- ИСПРАВЛЕНИЕ — номер исправления, обычно начиная с `00`.

РЕЛИЗ и ИСПРАВЛЕНИЕ содержат не менее двух десятичных цифр. Новый функциональный
выпуск увеличивает РЕЛИЗ и обнуляет ИСПРАВЛЕНИЕ. Исправление увеличивает только
последний номер. Первый функциональный выпуск нового года имеет вид
`vГОД.00.00`; исправления старых выпусков сохраняют их год.

## Исключение для первого публичного релиза

Первый публичный релиз — **v2026.00.01**. Это разовое исключение: сохраняем
версию, уже записанную в проверенной сборке. Она обозначает первый публичный
выпуск, а не исправление опубликованного v2026.00.00. Выпускать v2026.00.00
не требуется. Дальше действует обычная последовательность ниже.

| Публикация | Версия |
| --- | --- |
| Первый публичный релиз | `v2026.00.01` |
| Первое исправление после публикации | `v2026.00.02` |
| Следующее исправление | `v2026.00.03` |
| Второй функциональный релиз 2026 года | `v2026.01.00` |
| Первое исправление второго функционального релиза | `v2026.01.01` |

Следующий функциональный релиз посвящён системе автоматической загрузки и
установки Gateway: разработка, испытания, затем публикация. Детали реализации
определим отдельно. При публикации в 2026 году его версия — `v2026.01.00`.
Веб-интерфейс переносится на более поздний релиз.

## Соответствие сборки и публикации

Обозначения вроде r15 — внутренние номера сборок. Их хеши и исторические отчёты
сохраняются. Для первого публичного релиза не требуется пересборка только ради
версии или изменение `src/version.h`: там уже указана v2026.00.01. Решение о
номере не заменяет проверку артефакта, установки и работы на устройстве и само
по себе не публикует релиз.

Версия продукта независима от версии схемы сохраняемой конфигурации.
Опубликованные Git-теги и артефакты должны соответствовать проверенным исходникам
и бинарнику с SHA256. Опубликованный тег нельзя переназначать или повторно
использовать для другого содержимого.
