# Эксперимент UC-7420-LX / Linux 2.4: Web и RNG

Дата: 2026-09-12. Это промежуточная аппаратная проверка, не квалификация нового установочного пакета.

Прибор Moxa #4: UC-7420-LX без Plus, vendor OS 2.3, Linux 2.4.18_mvl30-ixdp425, glibc 2.2.5. Отдельная сборка GCC 3.3.2 использует `/lib/ld-linux.so.2`. Основная ветка v2026.02.03 для Plus/Linux 2.6 не изменялась и не публиковалась.

## Выявленные отличия

- CLOCK_MONOTONIC недоступен. Экспериментальный профиль использует `times()` при подтверждённых 100 Гц и 32-битном clock_t; системные календарные часы не используются для таймаутов. Переполнение счётчика проверено синтетическим целевым тестом. Продолжительная работа на реальном переполнении не проверена.
- Интерфейсы называются ixp0/ixp1 вместо eth0/eth1.
- Корень новой CF после vendor mount имел права 0777. RNG отказал до передачи свежей случайности. На подтверждённой новой карте права приведены к 0755. Установщик уже содержит нормализацию CF при start; её работу на этой ОС ещё требуется проверить.
- `/tmp` имеет права 0777 без sticky bit. Проверка доверенного пути IPC отказала. Для Linux 2.4 выбран `/var/4vrs-web-ipc` в RAM; строгие проверки каталога, владельца, inode и активного сокета сохранены. Для Linux 2.6 путь остаётся прежним.

## Область аппаратного теста

Использован отдельный каталог CF и диагностический исполняемый файл. Отличия от полного Gateway: пути Web/RNG, порты HTTP 18080 / HTTPS 18443, несекретные коды состояния и однократное чтение фактических интерфейсов вместо ещё не установленного сетевого владельца. Host-подмены RNG/CF не использовались. Проверка управления сетью этим не заменяется.

Все восемь UART отключены в конфигурации, NTP отключён, выбран HTTP. Заводской Apache на 80 не останавливался. Автозапуск не устанавливался. Первичная активация отдельного RNG выполнена со свежими 32 байтами через SSH с проверенным ключом; секреты в отчёты не выводились.

Первые попытки HTTP отказали: сначала отсутствовало подтверждённое наблюдение сети (код 60), затем не прошла проверка IPC-пути (код 4). Эти отказы сохранены как результаты локализации, не засчитаны как успешные тесты.

После исправления IPC выполнен ограниченный 30-секундный запуск:

| Запрос | HTTP | Размер | Время ответа |
|---|---:|---:|---:|
| / | 200 | 64551 байт | 0,031 с |
| /app.js | 200 | 13319 байт | 0,016 с |
| /style.css | 200 | 6053 байт | 0,015 с |
| /favicon.ico | 200 | 4260 байт | 0,016 с |

Запросы выполнялись через несколько секунд после запуска. Это не измерение времени от старта процесса до готовности и не измерение CPU. Авторизация, TLS и действия администратора в этом запуске не проверялись.

Web достиг state=2/error=0. По SIGTERM Gateway завершился с exit=0. После остановки RNG: ready, schema=3, generation=5. Между диагностическими запусками повторной активации и ручного удаления маркеров не было.

Пользователь отдельно подтвердил читаемое отображение `Gateway stopped / App closed / OS still running` на LCD. Выключение ОС этим не заявляется.

## Локальные проверки и оставшаяся работа

Application normal/UBSan: по 254 проверки; сценарий SAFE_MODE → SIGTERM → exit=10 и диагностика CLI прошли. Исправлены два устаревших ожидания v2026.02.01 в тестах: используется текущая константа версии. Panel: ранее 247 проверок, 0 ошибок. ABI последних Gateway/Web/RNG/KDF и диагностического Gateway проверен относительно сохранённых библиотек прибора.

Остаются профиль установщика, сетевой владелец и автозапуск, авторизация/KDF, TLS, UART/Modbus, удержание F2/F4 и питание/CF. Текущий установщик всё ещё ограничен Linux 2.6; новый установочный пакет пока не готов. Аппаратные результаты Plus/Linux 2.6 нельзя автоматически переносить на эту модель.

Локальные первичные результаты находятся в `outputs/moxa4-linux24`: `web-smoke-results.json`, `web-retry-http.json`, `web-retry-result.txt`, `web-retry-after.txt`, `ipc-open-paths.txt`. Последние retry-файлы относятся к успешному запуску; первичная неудачная HTTP-серия сохранена отдельно в web-smoke-results.json.
