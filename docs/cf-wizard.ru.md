# Установка и обновление CompactFlash — Ubuntu 24.04

> Актуальная [матрица выпуска](release-final.ru.md). Серия сокращена пользователем до 10 и завершена 10/10. Критерий аппаратного no-op закрыт; готово к выпуску в области матрицы. Повтор серии питания не требуется.

> Текущий кандидат — **web-ipc-v1**: [безопасное восстановление Web IPC после потери питания](web-ipc-lifecycle.ru.md). Аппаратная серия 10/10 завершена; прежний FAIL относится к старому кандидату.

> Текущий локальный кандидат включает [исправление медленного NV commit](rng-autonomous-v1-slow-commit.ru.md):
> ожидание RNG до 30 секунд, остановка после результата сохранения, совместимость установщика со schema 3.

Текущий локальный комплект — автономный RNG schema 3. Мастер проверяет schema 1/2/3, включая совпадение state/witness; новую CF готовит без включённой политики и требует однократную явную активацию. См. [политику и команды](rng-autonomous-v1.ru.md). Обычные рестарты не требуют сервиса.

[English](cf-wizard.md)

Автономный мастер для Ubuntu 24.04 **x86-64** и Moxa UC-7420-LX Plus. В комплекте
полный проверенный Web-кандидат и существующий native worker CF-bootstrap.
Мастер не подключается к Moxa и не меняет заводскую прошивку. Результат на PC —
**файлы проверены, активация ожидается**, а не завершённый ввод в эксплуатацию.

## Требование к заводской прошивке

Перед установкой 4VRS Gateway на **Moxa UC-7420-LX Plus** обновите заводскую
прошивку до **1.6** (`FWR_UC7400P_V1.6_Build_09110414`). Это обязательная
базовая версия для установки приложения по данной инструкции.

Проверьте на приборе:

```sh
kversion
```

Ожидаемый ответ:

```text
UC-7420-LX Plus firmware version 1.6
```

На дату проверки 2026-09-10 версия 1.6 — последняя опубликованная готовая
Linux 2.6.x-прошивка для этой платформы в [каталоге Moxa](https://www.moxa.com/en/products/phased-out-products/uc-7410%2C-uc-7420-series).
Указанная там версия 2.3 относится к Linux 2.4.x; не выбирайте образ только по
большему номеру версии. Образ должен соответствовать модели **LX Plus**.

Обновление заводской прошивки выполняется **до установки Gateway**, отдельно
от мастера CF и установщика приложения. Оно стирает данные и настройки внутренней
Flash: заранее сохраните нужные настройки и обеспечьте доступ через консоль.
Во время прошивки не отключайте питание. После перезагрузки повторите `kversion`
и проверьте сеть по [руководству производителя](https://www.moxa.com/Moxa/media/PDIM/S100000489/moxa-uc-7410-lx-plus-series-software-manual-v6.0.pdf),
раздел Upgrading the Firmware, страницы 3-4–3-5.

## Запуск в Ubuntu

Установите `python3 util-linux fdisk e2fsprogs udev unzip`. Сверьте SHA256 ZIP с
отчётом доставки. Распакуйте на PC, вне CF, в новый каталог root:

```sh
sudo install -d -m 0755 /opt/4vrs-cf-install-update
sudo unzip 4vrs-cf-wizard-v2026.02.01-final-review.zip -d /opt/4vrs-cf-install-update
cd /opt/4vrs-cf-install-update
sha256sum -c SHA256SUMS
sudo python3 cf-wizard.py --list
sudo python3 cf-wizard.py --report /root/cf-preparation-result.json
```

Имя отчёта должно быть новым. Отключите автомонтирование съёмных носителей,
закройте программы, использующие CF, и размонтируйте её через «Диски» Ubuntu.
Не меняйте карту и не запускайте другие дисковые утилиты во время работы.
Мастер не снимает чужие mount и не сбрасывает флаг read-only.

Выберите показанный ID после сверки USB VID:PID, serial картридера, точного размера,
разделов и UUID. Номер `/dev/sdX` не является постоянным идентификатором. Serial
принадлежит картридеру, а не обязательно карте. Системные и смонтированные диски,
swap, holders, составные устройства, не-USB и неоднозначные serial блокируются.
Если нельзя определить системный root-диск, запись запрещена. Принадлежность
разделов и идентичность носителя повторно проверяются непосредственно перед записью.

Введите имя выбранной Moxa, IPv4:порт и MAC LAN1 из доверенной описи, затем повторите
MAC. Жёсткой привязки к Moxa 1 нет. RNG привязан к MAC и UUID файловой системы;
сетевого поиска и подстановки другого прибора нет.

## 1 — Первая установка с полной очисткой

Введите точную фразу **ERASE-ALL-DATA** с USB ID, serial, размером и ID карты.
Будут удалены все данные, включая старый RNG, настройки и каталоги испытаний.
Старая ext3, `needs_recovery`, другие сигнатуры и старый RNG не блокируют явно
подтверждённую очистку. Старая ФС не монтируется, не исправляется; журнал не
воспроизводится. Резервная копия старых данных не создаётся. Список показывает
метаданные разделов; содержимое грязной ФС мастер не читает.

Мастер создаёт DOS/MBR, один Linux-раздел с сектора 2048 и совместимую ext3:
блоки 4096, inode 128, явно ограниченный набор старых возможностей. Проверяет новую
ФС, монтирует её, создаёт новое RNG существующим worker через `getrandom` PC и
записывает все 11 файлов полного Gateway-пакета. После размонтирования повторно
монтирует read-only, проверяет RNG и пакет, затем штатно размонтирует.
Повторная очистка требует нового явного подтверждения; молчаливой перегенерации
при повторе нет. Прерванная первая установка остаётся незавершённой.

## 2 — Обновление существующей установки

Нужны один совместимый чистый ext3-раздел в MBR, существующий Gateway, конфигурация
schema 1, 2 или 3 и действующий RNG с выбранными MAC/UUID. До mount выполняется
`e2fsck -f -n` без исправлений. Dirty/`needs_recovery` останавливает обновление до
монтирования. Не обходите проверку и не исправляйте журнал автоматически.
Отсутствующий/незавершённый RNG, чужая привязка, небезопасные права, симлинки и
неподдерживаемая schema означают отказ. В этой ветке RNG никогда не создаётся.

Первое монтирование: `ro,noload,nodev,nosuid,noexec`. Показываются занятое место и
экранированные имена верхнего уровня без обхода секретных данных. Подтвердите точную
фразу **UPDATE**. Полный пакет размещается отдельно:
`4vrs-packages/gateway-f519719cadca03b9`. Действующие `4vrs/bin`, настройки,
пароль администратора, TLS-сертификат/закрытый ключ и актуальный RNG не меняются.
Их содержимое не копируется в переносимый комплект и отчёт.

Запись идёт в новый root-каталог `.pending`: создание файлов без перезаписи, fsync
файлов/каталога и переименование только после проверки байтов и прав. Готовый
идентичный пакет проверяется повторно без перезаписи. Повреждённые или прерванные
данные вызывают отказ. Не удаляйте pending и не повторяйте операцию вслепую.
До запуска установщика на Moxa активная программа сохранена; отмена подготовки
на PC не требует отката программы.

## Отдельный первый запуск и активация на выбранной Moxa

После сообщения **Размонтировано** безопасно извлеките CF. В отдельно согласованное
окно обслуживания штатно выключите выбранный прибор перед вставкой/извлечением CF.
Сверьте адрес, MAC LAN1, UUID и mount `/var/hda`; другой прибор не подставляйте.
Сохраните прежний полный пакет и защищённую исходную базу восстановления. На Moxa:

Выполните команды из каталога пакета, указанного мастером:

```sh
./4vrs-install
./4vrs-install --status
```

Существующий установщик выполняет полное декодирование конфигурации, проверки
платформы, ABI пакета и startup, затем транзакционную активацию с журналами
восстановления. SSH может отключиться: после подключения проверьте
`/etc/4vrs-installer/recovery --status`. Запуск операции ещё не означает успех.
После разбора сбоя/прерывания штатная точка восстановления:
`/etc/4vrs-installer/recovery --recover`. Не удаляйте журналы. Автоматический откат
ошибочной транзакции не является универсальной командой downgrade. Старые кандидаты,
не читающие schema 3, требуют совместимой публичной конфигурации. При откате
программы нельзя возвращать устаревший RNG, пароль или TLS-состояние.

PC выполняет структурную проверку совместимости; полная проверка конфигурации и
startup остаётся за установщиком на приборе. Новый RNG сообщает `policy=required`:
мастер не создаёт `trial-policy` и не разрешает её применение. Первичный переход production-enable выполняется явно со свежим внешним входом по [инструкции](release-final-commissioning.ru.md). Секреты не вставляйте
в логи и отчёты; образ карты с приватным состоянием не включайте в доставку.

До ввода в эксплуатацию проверьте результат установщика, Gateway, требуемые UART/
Modbus, сеть, LCD и Web. Новая установка использует HTTP; обновление сохраняет
явный выбор HTTP/HTTPS и миграцию старого HTTPS. HTTP передаёт пароль и данные без
шифрования: используйте выделенную доверенную сеть управления. HTTPS доступен,
но не рекомендуется на этом устройстве из-за вычислительных затрат и задержек подключения.

Локальные испытания используют файловые образы, подменённую границу mount и публичный
тестовый RNG. Реальные mount, извлечение, потеря питания и ввод на приборе здесь
не квалифицированы. При ошибке сохраняйте файлы и проверьте mount; извлекайте карту
только после штатного размонтирования.
