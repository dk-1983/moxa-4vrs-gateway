# 4VRS Gateway

**Modbus-шлюз и прозрачный сервер последовательных портов для Moxa UC-7420-LX Plus.**

[English](README.md) · Русский · [Инструкция пользователя](docs/user-guide.ru.md)

![4VRS Gateway для Moxa UC-7420-LX Plus](assets/images/banner.png)

Восемь независимо настраиваемых портов RS-232 / RS-485 / RS-422 и управление
с дисплея самого устройства. Продукт работает поверх штатной Linux Moxa:
ядро и драйверы сохраняются.

**Статус:** готовим первый публичный релиз `v2026.00.01`.
Завершаем испытания, готовим установочный пакет и пользовательскую документацию.

## Возможности

| Функция | Реализация |
| --- | --- |
| P1–P8 | Независимые параметры; RS-232, RS-485 2/4-проводный, RS-422 |
| Modbus TCP | Запросы с заголовком MBAP по TCP, далее последовательный Modbus RTU |
| Modbus UDP | Запросы с заголовком MBAP по UDP, далее последовательный Modbus RTU |
| RTU over UDP | Кадры RTU с CRC в UDP-датаграммах |
| RAW TCP / RAW UDP | Прозрачная передача последовательных данных без разбора Modbus |
| Управление | Дисплей, кнопки, настройки, состояния портов, счётчики и диагностика |
| Сеть | Статика или DHCP-клиент LAN1/LAN2, маска, основной маршрут и DNS |
| Изменения сети | Review, временный Apply, подтверждение Keep, ручной/автоматический Revert |
| Время | RTC, NTP с интервалами 1/6/24 часа и диагностикой из трёх попыток |
| Сохранение | Восстановление настроек продукта и подтверждённой сетевой политики при загрузке |

Программа на компьютере или сервере подключается к Gateway по сети через TCP
или UDP. Gateway передаёт запросы подключённому прибору по RS-232, RS-485 или
RS-422 и возвращает его ответы программе. В Gateway и программе нужно выбрать
одинаковый транспорт: **Modbus TCP, Modbus UDP, RTU over UDP, RAW TCP или RAW UDP**.
Правила подключения и передачи данных для каждого режима описаны в таблице выше.

**На следующий релиз запланировано:**

- Система автоматической загрузки и установки Gateway, упрощающая установку для пользователя.
- Разработка и испытания системы, затем выпуск релиза.

Детали реализации определим отдельно. Веб-интерфейс переносится на более поздний релиз.

## Дисплей и локальное меню

<img src="assets/images/menu/home.png" alt="Главный экран и кнопки F1–F5" width="360">

*Изображение главного экрана.*

Главный экран показывает готовность приложения, готовые порты, ошибки и
клиентов. В этом примере готовы все восемь включённых портов, ошибок и клиентов
нет. Готовность порта ещё не доказывает ответ прибора. **F1 Help** открывает
справку, **F3 Menu** — главное меню. При переходе между настройками ориентируйтесь
на подсказки кнопок внизу дисплея. Настройка портов, Apply/Keep/Revert сети и NTP
описаны в [инструкции пользователя](docs/user-guide.ru.md).

<img src="assets/images/menu/main-menu.png" alt="Главное меню, выбран Status" width="360">

*Главное меню.*

**F2/F4** перемещают выбор, **F3** открывает раздел, **F1** возвращает назад.

| Раздел | Назначение |
| --- | --- |
| Status | Состояние приложения |
| Ports | Состояния и счётчики отдельных портов |
| Configuration | Параметры линии и транспорта, переход к настройкам сети |
| Diagnostics | Диагностика и события запуска |
| System | Дата и время, информация о платформе, NTP |
| Shutdown | Остановка Gateway; не выключает ОС Moxa |
| About | Название продукта и версия |

### Состояния портов

<img src="assets/images/menu/ports.png" alt="Список портов, выбран P1" width="360">

*Список портов.*

F2/F4 перемещают выбор среди P1–P8; список прокручивается к остальным портам.
**F3 Detail** открывает страницы состояния выбранного порта. `READY` означает
готовность порта, а не подтверждённый ответ подключённого прибора.

<img src="assets/images/menu/port-details.png" alt="Параметры подключения порта" width="360">

*Параметры подключения порта.*

Первая страница показывает UART, параметры линии, транспорт и слушатель.
В примере P1 использует `ttyM0`, RS485-2W, 115200 бод и Modbus TCP на порту 1502.
`8NONE1` означает 8 бит данных, без чётности и 1 стоп-бит (8N1). Это пример
настроек, а не заводские значения. F2/F4 переключают четыре страницы подробностей.

### Конфигурация и сеть

<img src="assets/images/menu/configuration.png" alt="Меню конфигурации" width="360">

F2/F4 выбирают порт, **F3 Select** открывает его настройки. **F5 Network**
открывает страницы LAN, основного маршрута и DNS.

<img src="assets/images/menu/network-lan2.png" alt="Подтверждённая политика LAN2" width="360">

*Сетевые настройки LAN2.*

**Confirmed policy** показывает принятые настройки. F2/F4 переключают страницы,
F5 открывает редактор, F1 возвращает назад. Изменения проходят Review → Apply → Keep;
во время подтверждения доступен Revert. Подробности — в [инструкции](docs/user-guide.ru.md#настройки-сети).

### Часы и NTP

<img src="assets/images/menu/network-time.png" alt="Настройки Network Time: NTP синхронизирован" width="360">

Откройте **System → F4 Platform → F5 Network Time**, чтобы посмотреть состояние синхронизации
и настройки. **F5 Edit** открывает редактирование NTP. Штатный интервал — 1, 6
или 24 часа; по умолчанию — 1 час. **F4 Test** запускает три попытки с интервалом
в минуту, после чего автоматически возвращается обычное расписание.

*Настройки сетевого времени.*

### Диагностика

<img src="assets/images/menu/diagnostics.png" alt="Счётчики диагностики" width="360">

*Счётчики диагностики.*

Откройте **Main Menu → Diagnostics**, чтобы посмотреть число принятых и
завершённых запросов, тайм-аутов, восстановлений, устаревших ответов и
максимальную глубину очереди. **F3 Events** открывает события запуска.

<img src="assets/images/menu/startup-events.png" alt="События запуска" width="360">

*События запуска.*

**F2/F4** переключают записи. В каждой показаны порядковый номер, этап запуска,
прогресс, результат и ошибка. `BOOT / Progress 0%` относится к выбранному
событию запуска, а не к текущей готовности приложения.

## Совместимость и установка

Аппаратные проверки выполнены на **Moxa UC-7420-LX Plus** со штатной средой
Linux для XScale big-endian. **UC-7410-LX Plus** и другие варианты UC-74xx
упоминаются как родственные модели; их совместимость пока не подтверждена.

Файлы продукта и настройки размещаются на CompactFlash в `/var/hda/4vrs/`.
На внутреннем накопителе остаётся минимальная интеграция запуска.

Публичный установочный пакет ещё готовится. Отдельный бинарник разработчика
не заменяет установку компонентов запуска, сети и часов. Артефакты и порядок
установки будут размещены в [Releases](https://github.com/dk-1983/moxa-4vrs-gateway/releases).

[Инструкция](docs/user-guide.ru.md) описывает управление установленной системой.
Первичная миграция сохраняет поддерживаемые настройки и сетевые адреса устройства.

## Значения новой конфигурации

Это значения для новой конфигурации продукта, а не инструкция по сбросу устройства.

| Параметр | По умолчанию |
| --- | --- |
| P1–P8 | Включены, RS-232, 9600 бод, 8N1 |
| Транспорт | Modbus TCP |
| Привязка слушателей | `0.0.0.0`, порты 502–509 соответственно |
| NTP | Выключен; штатный интервал — 1 час |
| Сеть | Статика предпочтительна; DHCP-клиент опционален, DHCP-сервера нет |

Регистрация сетевой конфигурации импортирует поддерживаемые существующие
настройки. Продукт не назначает универсальный заводской IP и не переводит
существующий DHCP в статику автоматически.

## Разработка и проверки

Исходники написаны на C; сборка использует отдельный штатный Moxa toolchain.
Подробности — в [описании среды сборки](docs/architecture/build-environment.md).
Заводские прошивки, SDK и руководства не распространяются вместе с проектом.

Используются host-тесты, выбранные проверки UBSan, аудит целевого ABI и
испытания на устройствах. [Статус проверок](docs/validation.ru.md)
различает доказанные результаты и незавершённые сценарии. Проверка компонента,
TCP-подключение и обмен с прибором подтверждают разные уровни работоспособности.

[Версия](docs/versioning.ru.md) имеет вид `vГОД.РЕЛИЗ.ИСПРАВЛЕНИЕ`, счётчики начинаются
с разовым исключением для первого выпуска: первый выпуск — `v2026.00.01`, следующий функциональный — `v2026.01.00`.
