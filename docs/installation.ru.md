# Автоматическая установка — v2026.01.00

[English](installation.md) · [Руководство](user-guide.ru.md) · [Проверки](validation.ru.md)

Нативный установщик работает в поддерживаемой Linux Moxa UC-7420-LX Plus.
Он сохраняет собственные сетевые, портовые и NTP-настройки устройства,
подготавливает сетевые/clock scripts и автозапуск. Python на Moxa, ручной enroll
и изготовление vendor derivative не нужны. Установщик не перезагружает устройство
и не является образом заводской прошивки.

Согласуйте окно обслуживания и резервный доступ: возможен обрыв SSH и обмена
с приборами. Сохраните внешнюю копию собственных настроек и startup files.
Проверьте цель и фактическое монтирование CF. Неподдерживаемая структура системы
отклоняется; не обходите отказ. Перед первым развёртыванием прочитайте
[границы проверок](validation.ru.md). Команды выполняйте отдельно; при ошибке
остановитесь. Проверку SSH host key не отключайте.

## Скачать и скопировать

**Компьютер — PowerShell**, в каталоге загрузок:
```powershell
Invoke-WebRequest -Uri 'https://github.com/dk-1983/moxa-4vrs-gateway/releases/download/v2026.01.00/4vrs-gateway-v2026.01.00.tar.gz' -OutFile './4vrs-gateway-v2026.01.00.tar.gz'
Invoke-WebRequest -Uri 'https://github.com/dk-1983/moxa-4vrs-gateway/releases/download/v2026.01.00/SHA256SUMS' -OutFile './SHA256SUMS'
Get-FileHash -Algorithm SHA256 './4vrs-gateway-v2026.01.00.tar.gz'
$moxaAddress = Read-Host 'Moxa IP'
$moxaSshPort = [int](Read-Host 'SSH port')
ssh -p $moxaSshPort "root@$moxaAddress"
```

Ожидаются SHA256 `852ba0816c467bb828fa9f15c07ee0e7e4a62cfb8b3e7446ef0a69bae9d4cc3f`
и размер225462 байта. SHA256SUMS относится к архиву этого выпуска.

**Moxa — SSH:** подтвердите root, свою Moxa, смонтированную CF `/var/hda` и место.
Родитель `/var/hda/4vrs/tests` должен существовать; при первом развёртывании
создайте его `mkdir -p /var/hda/4vrs/tests` только после проверки монтирования CF.
Создайте новый staging; существующий каталог сначала осмотрите, не перезаписывайте:
```sh
id
mount
df -k /etc /var/hda
test ! -e /var/hda/4vrs/tests/install-v2026.01.00
mkdir -m 700 /var/hda/4vrs/tests/install-v2026.01.00
```

**Компьютер — PowerShell**, в том же сеансе с переменными адреса/порта:
```powershell
scp -P $moxaSshPort ./4vrs-gateway-v2026.01.00.tar.gz ./SHA256SUMS "root@${moxaAddress}:/var/hda/4vrs/tests/install-v2026.01.00/"
```

## Установить и прочитать результат

**Moxa — SSH:** после передачи до распаковки ожидается MD5
`924d60987086c31534ce046282b4c7c2`. Распакуйте tar на Moxa для сохранения прав;
не переносите отдельно распакованные Windows-файлы без executable modes:
```sh
cd /var/hda/4vrs/tests/install-v2026.01.00
md5sum 4vrs-gateway-v2026.01.00.tar.gz
tar -xzf 4vrs-gateway-v2026.01.00.tar.gz
cd 4vrs-gateway-v2026.01.00
./4vrs-install
```

`operation started` означает запуск отделённого worker, а не завершение установки.
После восстановления связи с той же Moxa прочитайте сохранённый результат:
```sh
cd /var/hda/4vrs/tests/install-v2026.01.00/4vrs-gateway-v2026.01.00
./4vrs-install --status
```

| result | Значение |
| --- | --- |
| 0 | Операция завершена; проверить stage (обычно verify-installed; ремонт recovery — repair-recovery-executable) |
| 3 | Уже установлено и исправно/нет транзакции; лишний перезапуск не нужен |
| 100 | Последняя запись worker — выполнение; после прерывания/boot может быть устаревшей |
| 1 | Прежний набор восстановлен; новая установка не завершилась |
| 2 | Ожидание CF; не обходить защиту автозапуска |
| -1 | Отказ подготовки/входных данных; читать stage/detail |
| -2 | Требуется или не завершено восстановление; это не успех |

Exit0 у `--status` подтверждает чтение записи. Проверьте result/stage, сохранность
настроек и готовность приложения; TCP connect не доказывает обмен с прибором.
Для повтора выполните `./4vrs-install` из того же каталога пакета. Исправный
повтор не перезапускает службы и не заменяет настройки адресами другой Moxa.

## Обрыв и восстановление

Не удаляйте журналы, gates, lock и network store ради повтора.
Независимый recovery доступен до монтирования CF:
```sh
/etc/4vrs-installer/recovery --recover
/etc/4vrs-installer/recovery --status
```

После асинхронной операции перечитайте status. Если recovery ещё не опубликован,
повторите запуск того же проверенного пакета: на этой границе старые startup
entries ещё не изменены. При WAIT_CF восстановите доступность CF согласованным
безопасным способом и повторите recovery; не выдумывайте mount и не извлекайте
CF на ходу. Boot entries тоже восстанавливают незавершённую транзакцию; старый
result100 может остаться после успешного boot recovery — нужны фактические
файлы/службы. Приложение ждёт CF до120 секунд; после более позднего появления
может понадобиться повтор recovery/start. Повреждённый журнал требует диагностики
через резервный доступ. Recovery незавершённой транзакции не является downgrade.

## Подсветка и сохранённый ручной путь

**System → Display → Backlight → On / Off**, F3 сохраняет. По умолчанию On;
старый config без поля тоже использует On. При Off экран/кнопки работают,
сохранённое значение возвращается после boot. [Подсветка](backlight.ru.md).
Старые декодеры несовместимы с Off в основном config и backup: простой откат
бинарника недопустим без проверки совместимости.

Сохранённая ручная процедура в [руководстве](user-guide.ru.md) относится к
предыдущему выпуску с ручной интеграцией. Не выполняйте её поверх active journal
этого установщика и не подменяйте ELF в пакете. Она сохранена после автоматического пути.
