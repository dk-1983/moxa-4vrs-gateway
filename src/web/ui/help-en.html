Getting started and controls

A new installation without saved configuration enables HTTP on LAN1. Existing installations without a protocol field retain HTTPS; updates preserve saved choices, including Disabled. Select HTTP or HTTPS (TLS) in Web System or LCD System → Web Server. Only the selected protocol listens. HTTP is unencrypted: passwords and data are sent in clear text; authentication and local recovery confirmation are still required. HTTP is recommended for a dedicated trusted management network and remains the default for new installations. HTTP sends passwords and data without encryption. HTTPS (TLS) remains available, but is not recommended on Moxa UC-7420-LX Plus. Upgrades preserve explicit HTTP/HTTPS choices; schema 1/2 configurations without a protocol field retain legacy HTTPS. A single-client limit and password hashing do not protect data transmitted over HTTP. Compare its certificate SHA-256 with the LCD before trusting it. Changing protocol revokes sessions; use the new address and sign in again. Failed startup of a newly selected mode restores the previous working mode; LCD remains available. One Web TCP connection is admitted globally, including an incomplete handshake. Other connections are closed before TLS; an active connection is never evicted. Close other Web tabs and wait for an idle connection to expire before reconnecting.

The first administrator is created with the temporary code displayed on the device and your own password. A code is valid for three minutes, with at most five attempts. It is not a default password. After expiry, request a new code from System → Web Server on the panel. Subsequent sign-in needs only the administrator password. Passwords occupy 12–128 UTF-8 bytes; many non-ASCII letters occupy two or more bytes.

Save, Cancel and network confirmation

For a port, edit its serial parameters and endpoint, then Save. Cancel leaves the saved configuration unchanged. A stale draft is refused if another interface has changed the settings; reopen the page and review again.

Network draft → Review (old → new, all four groups)
              → Apply → reconnect if the address changes
                      → Keep before the deadline → saved
                      → Revert / timeout → previous network

Review itself changes nothing. Keep confirms the active network operation; Save on an ordinary settings form submits a configuration change. An accepted request is not proof that activation succeeded: check the resulting state. Do not submit a new network draft while confirming an earlier operation.

Gateway settings

Use Ports to set P1–P8 independently. Match electrical mode, baud rate, data bits, parity and stop bits with the attached device. The TCP/UDP port is a network endpoint number, not the P1–P8 connector number. Bind IP limits the local address. Check special baud support against the attached equipment before enabling it.

Network contains four shared groups: LAN1, LAN2, Default route and DNS. Static mode uses the supplied IP, mask and gateway. DHCP mode gets the active address from a DHCP server; stored static fields remain in your draft. The default route selects the interface for destinations outside connected networks. DNS Manual uses DNS1/DNS2; DNS DHCP selects a lease source. Selecting a DNS source does not enable DHCP on that LAN. Review all groups together before Apply.

System contains manual clock setting and NTP settings, including Test and Stop test. NTP Disabled does not mean the current clock is untrusted: manually set or previously synchronized time can remain trusted. Check the reported clock state and test result separately.

Backlight

System → Display controls the local display backlight. Off is a saved setting and survives update. It does not stop Gateway.

Connections and cables

On UC-7420-LX Plus, LAN1/LAN2 are Ethernet, P1–P8 are configurable serial ports, and Console is a separate RS-232 management port. Their RJ45 shape does not make their electrical functions interchangeable. USB, CompactFlash and PCMCIA are separate connectors.

The matching Plus hardware manual specifies 12–48 VDC. Check the actual device label before connection. Connect protective/shield ground to an appropriate grounded metal surface before connecting other devices. The manual’s power drawing identifies SG as the leftmost terminal in its illustrated view; follow the marked SG/V+/V− terminals on the device, not an unlabelled rotated connector.

Maintenance and recovery

CompactFlash at /var/hda holds application binaries, saved configuration and private Web security data. Early installer recovery lives under /etc/4vrs-installer so it can guard startup while CF is absent. Do not remove CF during operation or writing.

Run these commands in a device shell, from the directory containing the verified installer package:

./4vrs-install
./4vrs-install --status

Installation starts an independent operation. A disconnected SSH session does not prove success or failure. After reconnecting, inspect the durable result:

/etc/4vrs-installer/recovery --status

The result names the stage and outcome. If recovery is required, preserve the result and obtain operator assistance before retrying. The existing recovery entry supports an explicit recovery operation:

/etc/4vrs-installer/recovery --recover

This command changes the installation state; use it only for the identified interrupted update. Do not remove journal files manually. Installer disables vendor Apache startup as part of its transaction while preserving Apache files; a rollback restores its previous state.

Stop Gateway from the confirmed System action before service maintenance. This stops the application, not the operating system or power. Use the site’s approved OS shutdown procedure before removing storage or power. Console access requires the correct RS-232 cable and the device’s verified console settings; it is not Ethernet.

To change a known password, use System → Security → Change password, supply the current password and repeat the new one. Successful replacement signs out all sessions. Forgotten-password recovery requires local confirmation and a temporary code from the display. The old password remains valid until the replacement is durably saved.

PCMCIA wireless expansion is mentioned in the Plus manual as optional hardware. This does not establish Wi-Fi or arbitrary PCMCIA driver support in 4VRS Gateway.

Diagnostics and questions

Ready ports versus alarms?
Overview compares ready ports with enabled ports. Active port alarms are current lifecycle problems. Accepted/completed/timeouts/recoveries/stale and queue high-water are cumulative runtime counters in Diagnostics; they are not all active alarms.
Link down or timeouts?
Check observed link, selected LAN, endpoint, serial mode and peer parameters. A timeout shows that a request did not finish in its time budget; it does not alone prove broken wiring. Compare CRC/framing counters and recent startup events before changing settings.
Saved Enabled but Web is not Running?
Inspect the local Web error and selected IP. Missing CF, insufficient entropy, untrusted time, unavailable interface or a listener conflict can prevent HTTPS startup. Another service on 80/443 must be identified; do not stop an unknown process blindly.
Certificate warning or changed fingerprint?
Use the current local fingerprint and selected IP addresses. Address changes or certificate renewal can change the certificate while preserving its private key. Never export the private key to compare identity.
Network page lost connection after Apply?
Reconnect to the proposed address and Keep within the deadline. If you cannot reconnect, wait for automatic rollback and return to the prior address. Do not assume the last displayed value is current after a failed refresh.

HTTPS is not recommended for this device due to additional processing overhead and connection delays. Password verification during sign-in causes a temporary high CPU load — approximately 92% in testing — regardless of the protocol.

After optimization, normal Web panel use places little load on the processor: in the user-operated HTTP test, the Web process averaged approximately 0.06% CPU, excluding the separate password-verification process. After sign-in, the interface is responsive in both modes.
